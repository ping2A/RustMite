IronSift Platform

Clear workflows: ingest data, run detection, visualize fleet anomalies, and tune AnoMark.

IronSift ingests host telemetry (process and/or file inventory), runs fleet clustering and optional AnoMark scoring, and surfaces findings on a honeycomb. Use the tabs above for each phase.

Typical workflow

  1. Import CSV / JSON / JSONL under Ingestion and confirm rows in Inspect.
  2. Under Runs & Findings, pick datasets and start a detection run (IronSift fleet, optional AnoMark).
  3. Read the honeycomb and findings table; severity reflects fused detectors.
  4. Optionally train or score AnoMark and run Sigma checks from their tabs.

    Open results in new tab

    The preview lists datasets only when you use checkboxes, comma-separated ids, and/or baseline or candidate tags. It stays empty until then; starting a run with ids and tags both empty still applies to every dataset on the server. Baseline and candidate fields restrict inclusion (a dataset is included if any of its tags match a tag you list in either field). The preview updates as you type. If tag filters match nothing, the server returns 400—check spelling and Ingestion tagging. If you select more than one dataset, the same host name in two files is analyzed as two separate machines (snapshots are not merged).

    Runs ▼

    Score process datasets

    To run the trained model over your data, use a detection run: open Runs & Findings → Create Detection Run, enable Include AnoMark, pick process datasets (or ids/tags), then Run. Findings include AnoMark suspicious-command ratios per host together with other detectors. After training, the platform model updates automatically; you can also pick a saved training in the run form.

    AnoMark Training

    POST /api/anomark/train accepts the fields below (process datasets only). dataset_ids merges checked rows with the extra ids field; tags requires each dataset to have at least one listed tag. If training_path is set, it replaces dataset-built input.
